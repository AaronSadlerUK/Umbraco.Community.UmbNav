# UmbNav V18 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship an Umbraco 18-compatible UmbNav (package 5.x) on a new `dev/v18` branch while keeping the LTS line (`dev/v17`, package 4.x) as the active development lane, with a V18 test site and per-branch CI.

**Architecture:** Branch-per-major (Model A), LTS primary. `dev/v17` stays active (4.x, Umbraco 17); `dev/v18` is the forward-port line (5.x, Umbraco 18). No single package spans both majors — users pick by Umbraco major. Both majors target `net10.0`, so the only differences are dependency versions and a small set of API breaks catalogued by a spike.

**Tech Stack:** .NET 10, Umbraco CMS 17/18, xUnit + Moq, TypeScript + Lit 3, Vite, Vitest, GitVersion 6, GitHub Actions.

## Global Constraints

- **Dependency ranges are single-major floor/ceiling.** `dev/v17` → `[17.0.0, 17.999.999)`; `dev/v18` → `[18.0.0, 18.999.999)`. Applies to `Umbraco.Cms.Web.Common` (Core), and `Umbraco.Cms`, `Umbraco.TheStarterKit`, `uSync` (test site).
- **Package majors:** Umbraco 17 → UmbNav 4.x; Umbraco 18 → UmbNav 5.x.
- **Two branches only.** `develop` is retired. `dev/v17` (LTS, active), `dev/v18` (STS, forward-port), plus `main` (stable tracking).
- **One test site per branch.** `TestSite.V17` exists only on `dev/v17`; `TestSite.V18` only on `dev/v18`.
- **Forward-port direction:** new work lands on `dev/v17` first, cherry-picked forward to `dev/v18`.
- **TFM is `net10.0`** on both branches. Node 23. Solution file is `UmbNav.slnx`.
- **No `npm run typecheck` script exists** — typecheck with `npx tsc --noEmit` (run inside `./Umbraco.Community.UmbNav/`).
- Frontend `RestorePackagesWithLockFile` / `packages.lock.json` are in use — regenerate lock files with `dotnet restore --force-evaluate` after any C# package change.
- Commit after every task. Do not push or delete remote branches without the maintainer's explicit go-ahead (repo convention: git actions only when asked).
